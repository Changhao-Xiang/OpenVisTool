\begin{abstract}
Visual tool use has emerged as a fundamental capability for multimodal agents to actively acquire evidence beyond a single image representation.
Existing approaches learn this capability from teacher-generated trajectories, implicitly assuming that every successful demonstration provides effective supervision.
We argue that this assumption is fundamentally flawed: task success does not necessarily imply useful supervision, as many tool interactions are incidental to the final answer rather than contributing to evidence acquisition.
We present \textbf{OpenVisTool}, an open framework for constructing \textit{instructive visual tool-use trajectories} that provide effective supervision for tool learning.
Our key insight is that a trajectory should be retained only if its visual observations demonstrably improve performance on the target query.
Guided by this principle, OpenVisTool combines difficulty-aware query selection, domain-guided trajectory synthesis, and a novel dual rejection strategy that jointly verifies answer correctness and observation utility.
Rather than encouraging models to imitate tool calls, the resulting supervision teaches when and how visual evidence should be acquired.
Using this framework, we build \textbf{\dataset}, a cross-domain visual tool-use dataset spanning five representative domains, together with \textbf{\benchname}, a benchmark for evaluating visual tool-use capability.
Experiments across multiple model families show consistent performance improvements across domains and generalization to unseen benchmarks, suggesting that effective visual tool use is learned from high-quality supervision rather than domain-specific tool-calling patterns.
\end{abstract}

A strong teacher can often reach the right answer without any visual tools (via parametric knowledge, reasoning shortcuts, or coarse image cues in the static encoding), yet still issues tool calls simply because the synthesis prompt instructs it to~\citep{hou2025codev,zhao2026focus}.
Such trajectories pass outcome-based filtering while providing \textit{spurious supervision}: the visual observations appear in the reasoning trace but make no causal contribution to the answer. 
A student trained on such data thus learns correlation rather than causation: it learns that tool calls \textit{accompany} correct answers, not that tool observations \textit{ground} them.

This failure mode is invisible to any filter that inspects only outcomes. Answering the open question above thus requires shifting the object of evaluation from whether a trajectory ends correctly to whether its tool calls do real work: \textit{would the answer still hold if the visual observations were taken away?}
  
  
  
  
We argue that a trajectory constitutes beneficial supervision for visual tool-use learning only when it satisfies two conditions jointly. The first is outcome validity: the trajectory must arrive at a correct final answer, ensuring the model is not trained on erroneous reasoning chains. The second—and the one overlooked by existing pipelines—is causal utility: the visual observations returned by tools must causally contribute to reaching that answer. That is, if we counterfactually remove the tool observations from the trace, the reasoning should no longer succeed. A trajectory meeting both conditions teaches the model not merely that a tool can be called, but why the call was necessary—because it supplied evidence that the model's intrinsic visual encoding could not provide. Together, these two conditions reframe trajectory selection from a post-hoc quality filter into a principled causal supervision selection mechanism: rather than ``did this trajectory produce a correct answer?'', we ask ``did the tool observation cause the correct answer?'' This causal framing directly operationalizes the distinction between correlation and causation raised above, and provides a concrete, testable criterion for identifying trajectories from which a model can genuinely learn the skill of visual evidence acquisition.

Guided by this insight, we design OpenVisTool, a three-stage trajectory synthesis pipeline that operationalizes causal supervision selection across five diverse visual reasoning domains—Chart, Table, GUI Grounding, Visual Search, and Web-to-HTML—under one shared visual toolset. Stage 1: Difficulty Screening filters for problems where a capable model without tool access fails, ensuring the retained questions genuinely demand external visual evidence. Stage 2: Domain-Specific Tool-Use Patterns defines structured invocation strategies tailored to each domain, guiding the teacher to produce coherent traces rather than arbitrary tool calls. Stage 3: Dual Rejection Sampling enforces both conditions of beneficial supervision by discarding trajectories that are either answer-incorrect or whose tool observations fail to causally improve a base model's performance. Together, the three stages form a progressive funnel: Stage 1 ensures the problem requires tools, Stage 2 ensures the process uses tools coherently, and Stage 3 ensures the outcome causally depends on tool observations. To enable standardized evaluation of this capability, we further introduce a comprehensive benchmark covering diverse visual tool-use scenarios, allowing reproducible comparison across both open-source and proprietary models.

Across four backbones from 4B to 27B parameters, fine-tuning on \dataset consistently improves the five-domain average (e.g., Qwen3.5-9B rises from $32.6$ to $45.8$) and transfers to out-of-distribution agentic benchmarks. Ablations further show that the intersection of answer correctness and positive tool-use gain outperforms either filter alone, supporting the central claim that effective visual tool use is learned from instructive trajectories.
