\begin{abstract}
Visual tool use has emerged as a fundamental capability for multimodal agents to actively acquire evidence beyond a single image representation.
Existing approaches learn this capability from teacher-generated trajectories, implicitly assuming that every successful demonstration provides effective supervision.
We argue that this assumption is fundamentally flawed: task success does not necessarily imply useful supervision, as many tool interactions are incidental to the final answer rather than contributing to evidence acquisition.
We present \textbf{OpenVisTool}, an open framework for constructing \textit{instructive visual tool-use trajectories} that provide effective supervision for tool learning.
Our key insight is that a trajectory should be retained only if its visual observations demonstrably improve performance on the target query.
Guided by this principle, OpenVisTool combines difficulty-aware query selection, domain-guided trajectory synthesis, and a novel double rejection strategy that jointly verifies answer correctness and observation utility.
Rather than encouraging models to imitate tool calls, the resulting supervision teaches when and how visual evidence should be acquired.
Using this framework, we build \textbf{\dataset}, a cross-domain visual tool-use dataset spanning five representative domains, together with \textbf{\benchname}, a benchmark for evaluating visual tool-use capability.
Experiments across multiple model families show consistent performance improvements across domains and generalization to unseen benchmarks, suggesting that effective visual tool use is learned from high-quality supervision rather than domain-specific tool-calling patterns.
\end{abstract}

\section{Introduction}
\label{sec:introduction}

Large language models can become more capable when equipped with external tools \citep{schick2023toolformer,chen2024unlocking}: a code interpreter handles arithmetic that free-form generation gets wrong \citep{xue2025simpletir,feng2025retool}, and search injects knowledge outside the model's parameters \citep{jin2025searchr1,Search-o1,Li2025WebThinker}. The common mechanism is that a tool returns an observation that is difficult for the model to produce on its own. Multimodal models face an analogous limit, except the missing information is visual: a single static encoding of an image often fails to expose the evidence a question requires. Visual tools address this limit either by surfacing details that a fixed view cannot resolve, as when cropping reveals small axis labels \citep{chartagent}, or by closing a generate--verify loop, as when generated HTML is rendered against a reference \citep{ui2coden2026}. In both cases, the model acts on visual inputs and feeds newly acquired evidence back into reasoning, a paradigm now described as ``think with images'' \citep{openai2025o3,su2025thinkingsurvey,zheng2026deepeyes}.

Recent visual tool-use systems commonly acquire this capability from teacher-generated trajectories: a model is first cold-started with supervised fine-tuning (SFT) and then further optimized with reinforcement learning (RL) \citep{lai2026minio3,hou2025codev,guo2025codevision}. Prior work has found that RL alone may fail to bootstrap stable tool use, making the cold-start trajectories indispensable \citep{hong2026deepeyesv2,zhang2026thyme}. Yet this dependence exposes a more basic question: which teacher trajectories are actually valuable for learning visual tool use? Existing synthesis pipelines often answer this question with outcome-based rejection sampling or judge-based quality rating, retaining trajectories that are well-formed, executable, and answer-correct. For visual tool learning, however, correctness is not enough. A teacher may answer correctly while making incidental tool calls whose observations do not affect the answer; such traces teach tool-call mimicry rather than evidence acquisition.

We therefore frame trajectory construction around observation utility. An instructive visual tool-use trajectory should teach models when and how to acquire useful visual evidence. Operationally, it should satisfy three conditions. First, the query should require visual evidence that a base model cannot reliably recover from the original view alone. Second, the trajectory should reach the correct answer, so the demonstration is valid. Third, and most importantly, the observations produced by the tools should themselves improve task performance, rather than merely co-occurring with a successful teacher answer. This definition separates trajectories that expose reusable visual evidence from trajectories that are only superficially successful.

We present \method, an open framework that constructs such instructive visual tool-use trajectories across domains. \method first applies difficulty-aware query selection, removing examples that a base model already solves without tools. It then synthesizes trajectories with a strong teacher under a shared visual toolset, while domain-guided tool-use patterns encourage operations tied to each domain's visual bottleneck. Finally, a double rejection strategy retains a trajectory only when it is both answer-correct and tool-beneficial. The tool-use gain test measures whether a fixed probe model solves the same query more reliably when given only the teacher's tool observations as additional context. Since the teacher's reasoning is withheld, positive gain indicates that the observations are usable evidence rather than decorative calls.

Applying this framework, we build \dataset, a dataset spanning Chart, Table, GUI Grounding, Visual Search, and Web-to-HTML under one shared visual toolset. We also introduce \benchname, a benchmark designed to evaluate whether models can leverage visual tools rather than only solving tasks from static images. Across four backbones from 4B to 27B parameters, fine-tuning on \dataset consistently improves the five-domain average (e.g., Qwen3.5-9B rises from $32.6$ to $45.8$) and transfers to out-of-distribution agentic benchmarks. Ablations further show that the intersection of answer correctness and positive tool-use gain outperforms either filter alone, supporting the central claim that effective visual tool use is learned from instructive trajectories.

In summary, our contributions are:
\begin{itemize}
  \item We present \textbf{\method}, an open cross-domain framework that synthesizes \textit{instructive} tool-use trajectories through difficulty-aware query selection, domain-guided trajectory synthesis, and double rejection sampling on answer correctness and tool-use gain.
  \item We release \textbf{\dataset}, a visual tool-use trajectory dataset over Chart, Table, GUI Grounding, Visual Search, and Web-to-HTML under one shared visual toolset, together with \benchname for evaluating visual tool-use capability.
  \item We show that fine-tuning on \dataset improves all five domains across four backbones spanning 4B to 27B parameters, generalizes to out-of-distribution tasks, and outperforms alternative filtering strategies.
\end{itemize}
