\section{Introduction}
\label{sec:introduction}

Large language models become more capable when they call external tools during reasoning: a code interpreter handles the arithmetic that free-form generation gets wrong \citep{feng2025retool}, and search injects knowledge outside the model's parameters \citep{yao2023react,schick2023toolformer,jin2025searchr1}. The common mechanism is that a tool returns an observation the model could not have produced on its own. Multimodal models face the analogous limit, except the missing information is visual: a single static encoding of an image often fails to expose what a question requires. Visual tools relieve this in two ways---they \emph{surface evidence} a fixed view cannot resolve (cropping to read small axis labels, locating an occluded object) and \emph{close a generate--verify loop} (rendering generated HTML against a reference). In both, the model acts on the visual input and feeds the result back into its reasoning: the paradigm of \emph{thinking with images} \citep{openai2025o3,su2025thinkingsurvey}.

These capabilities are instilled by training. The prevailing recipe is a two-stage pipeline: cold-start supervised fine-tuning (SFT) on curated visual tool-use trajectories, then reinforcement learning (RL). Recent systems such as DeepEyesV2 \citep{hong2026deepeyesv2}, Thyme \citep{zhang2026thyme}, and Mini-o3 \citep{lai2026minio3} follow this template, and several report that RL alone fails to bootstrap stable tool use, making the cold-start stage indispensable. This places the trajectory corpus at the center of the pipeline. Yet such corpora are assembled in-house, specialized to one or two domains, and seldom released, leaving no general source of visual tool-use supervision. We therefore treat the \emph{data}, not the training algorithm, as the lever \method pulls.

The recipe shared across these in-house pipelines distills from a strong teacher and keeps a trajectory whenever its final answer is correct. This filter is too weak: a teacher can reach the right answer through incidental tool calls, so final-answer correctness reveals neither whether the task needed tools nor whether the recorded observations helped. A corpus assembled this way teaches the model to imitate tool-use syntax rather than to invoke tools when they genuinely help.

\method instead requires a retained trajectory to satisfy two conditions: the task should benefit from tools, and the recorded outputs should measurably improve solving it. As a pre-screen \emph{before} synthesis, we discard queries a base model already solves without tools, so external evidence has room to help. We then roll out a strong teacher under a shared visual toolset, steered by a per-domain tool-use pattern that fixes which operations are canonical for each domain's visual bottleneck. Finally, \emph{double rejection sampling} keeps a synthesized trajectory only when it is both \emph{answer-correct}---under domain-appropriate evaluators (rule-based matching, an LLM judge, or render-based VLM judging for Web-to-HTML)---and \emph{tool-beneficial}: prepending the teacher's observations, without its reasoning, to a base model's context must measurably raise its accuracy. The main \dataset is the intersection.

\dataset contains 42K trajectories across five domains with complementary visual bottlenecks---Chart and Table (fine-grained reading, structural alignment), GUI Grounding (coordinate precision), Visual Search (active search in clutter), and Web-to-HTML (a generate--render--revise loop)---all sharing one visual toolset, so the model learns reusable operations rather than a separate interface per task. Fine-tuning improves all five domains across four backbones spanning two model families and 4B--27B scale; on Qwen3.5-9B the average rises from 32.6 to 45.8, with the largest gains where tools expose otherwise-hidden evidence (Visual Search $+23.8$, Table $+17.3$). Controlled variants confirm the design: each filter alone underperforms their intersection, and tool-use supervision beats a no-tool-trajectory SFT baseline on the same queries by 8.7 points. The advantage is sharpest when tools acquire new visual evidence.

In summary, our contributions are:
\begin{itemize}
  \item We present \method, an open recipe for synthesizing cross-domain visual tool-use trajectories: it pre-screens out queries a base model already solves without tools, then applies \emph{double rejection sampling}, retaining a trajectory only when it is both answer-correct and tool-beneficial---its observations measurably raise a base model's accuracy---so the supervision teaches evidence acquisition rather than tool-call mimicry.
  \item We release \dataset, a 42K-trajectory corpus over Chart, GUI Grounding, Table, Visual Search, and Web-to-HTML under one shared visual toolset, with domains chosen for complementary visual bottlenecks, as open cold-start supervision for agentic vision models.
  \item We show that fine-tuning on \dataset improves all five domains across four backbones spanning two model families and 4B--27B scale, with controlled variants and a dedicated analysis establishing that the correctness filter and the tool-use gain filter are complementary and that tool-use supervision outperforms no-tool trajectories on evidence-acquisition domains.
\end{itemize}
