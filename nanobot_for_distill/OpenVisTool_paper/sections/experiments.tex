\subsection{Experimental Setup}
\label{sec:setup}

\subsubsection{Evaluation Benchmark}
% KEEP the framing below: the benchmark is, by design, a visual-tool-use
% diagnostic; the per-domain selection mechanism differs but the principle is one.

\paragraph{Design goal.}
\benchname is built so that visual tool use is \emph{decision-relevant}: a model with strong tool-use ability should score clearly higher than one that only reads a static view. We therefore retain, per domain, the instances on which tool use is necessary or beneficial rather than sampling the source benchmarks uniformly.

\paragraph{Per-domain construction (one principle, two mechanisms).}
All five domains concentrate on tool-decisive instances; only how we obtain them differs with what each source affords.
\begin{itemize}
\item \textbf{Chart and Table} --- source QA pools (CharXiv-reasoning $+$ ChartMuseum; MMT-Bench $+$ TableVQA-Bench) are dominated by tool-irrelevant questions, so we \emph{explicitly select}: keep an instance when giving tools raises avg@$5$ above the no-tool avg@$5$ \emph{yet stays below $1$} (a measurable gain, with headroom left). Selection uses the \emph{union} of three third-party strong models (GPT-5.4, Gemini-3.0-Flash, Qwen3.5-Plus); the criterion is ``tools \emph{in principle} help'' (model-agnostic), not ``\emph{our} toolset helps,'' which avoids circularity with the evaluated students.
\item \textbf{GUI, Visual Search, Web-to-HTML} --- the source benchmark is \emph{already} curated for the corresponding visual operation, so we adopt it directly: the smallest-target subset of ScreenSpot-Pro (117 items), VisualProbe-Hard, and Vision2Web-Level1. An additional avg@$5$ filter here would shrink the set below a usable size, so none is applied.
\end{itemize}

\paragraph{Scoring.}
Per-domain evaluators match the source task: extractor $+$ voting LLM judge giving $0/1$ for Chart, Table, and Visual Search; geometric point-in-bbox for GUI; and component-level visual fidelity ($0$--$100$, rendered HTML vs.\ reference) for Web-to-HTML. We report per-domain scores and their average, at avg@$k$.

\paragraph{Full-set control (Chart/Table).}
% Neutralizes the "you rigged the benchmark for tools" critique.
Because only Chart and Table are selected by us, we additionally report these two on the \emph{unfiltered} original sets to show the selection \emph{concentrates} rather than \emph{manufactures} the gain (smaller but positive). \subsubsection{Student Models and Training}

\paragraph{Backbones and training.}
We fine-tune four backbones spanning two model families and 4B--27B scale --- Qwen3.5-4B/9B/27B and Qwen3-VL-8B-Instruct --- on \dataset for three epochs with ms-swift, tools enabled at inference. Optimization details are in the appendix.

\subsubsection{Inference Protocol and Baselines}

\paragraph{Protocol.}
``With tool'' runs the fine-tuned model as a tool-using agent over the shared visual toolset (up to a fixed tool-round budget); ``w/o tool'' runs the same backbone single-pass without tools. Metric is per-domain accuracy and the average, at avg@$k$.

\paragraph{Baselines.}
Three groups: (i) the \emph{no-tool} base backbones; (ii) released visual tool-use models \textbf{Thyme} and \textbf{DeepEyesV2}, both on Qwen2.5-VL-7B --- a base mismatch with our students, so we frame this as a comparison to \emph{released models}, not a controlled comparison \TODO{Optionally train \dataset on Qwen2.5-VL-7B for an apples-to-apples row.}; and (iii) data-variant baselines (correctness-only, tool-gain-only, and a no-tool-trajectory SFT on the same queries), defined here and used in \S\ref{sec:ablation_gain}.

\subsection{Main Results}
\label{sec:main_results}

\paragraph{\dataset improves every backbone and every domain.}
The average rises for all four backbones (Qwen3.5-4B $30.8\!\to\!41.5$, 9B $32.6\!\to\!45.8$, 27B $38.8\!\to\!49.3$, Qwen3-VL-8B $24.0\!\to\!32.9$), across two families and 4B--27B scale.

\paragraph{Gains concentrate where tools surface new evidence.}
Largest improvements are on the evidence-acquisition domains, Visual Search and Table (Qwen3.5-9B: $+23.8$ and $+17.3$); domains answerable from a static view gain least. (Why: \S\ref{sec:cross_domain}.)

\paragraph{Released tool-use models do not transfer cross-domain.}
On the same shared base, Thyme ($18.2$) and DeepEyesV2 ($15.5$) fall \emph{below} the no-tool base ($19.2$) on the five-domain average, collapsing on out-of-specialty domains (DeepEyesV2: Web2HTML $2.4$, GUI $1.7$) --- motivating a single cross-domain corpus rather than narrow-domain data.

\subsection{Ablation: Double Rejection Sampling}
\label{sec:ablation_gain}
\label{sec:notool_traj}
% Two distinct claims live in one table; keep them as two paragraphs.

\paragraph{Setup.}
All variants train Qwen3.5-9B on the same queries for a fixed budget (1{,}971 steps), isolating the retention rule: full \dataset (correctness $\cap$ \toolgain), correctness-only, tool-gain-only, and a no-tool-trajectory SFT.

\paragraph{Tool-use supervision beats text-only supervision.}
Every tool-use variant outperforms the no-tool-trajectory SFT on average (\dataset $45.8$ vs.\ $37.1$, $+8.7$), so the gain comes from the \emph{tools}, not merely from SFT on these (hard) queries.

\paragraph{The filtering strategy matters.}
The intersection dominates either filter alone: $45.8$ (both) $>44.1$ (correctness-only) $>42.4$ (tool-gain-only), with the widest margins on Table and Visual Search --- evidence that correctness and \toolgain are complementary (correctness removes invalid demos; \toolgain removes causally useless ones).

\subsection{Cross-Domain Transfer and the GUI Exception}
\label{sec:cross_domain}
% Folded in from the former Discussion section.

\paragraph{Single-domain training transfers, asymmetrically.}
Fine-tuning Qwen3.5-9B on each single-domain slice and evaluating on all five shows out-of-domain gains (e.g.\ GUI-only raises Visual Search $35.6\!\to\!52.8$; Visual-Search-only raises Table $25.8\!\to\!40.9$), suggesting some behaviors --- localized inspection, grounding evidence before answering --- are reusable.

\paragraph{No single domain replaces the full mixture.}
Full \dataset is best on average and on four of five domains, so the multi-domain mix is doing real work.

\paragraph{The GUI exception (a diagnostic).}
GUI is the only domain where both the GUI-only slice ($36.3$) and no-tool-trajectory SFT ($40.0$) beat the full corpus ($31.6$): under a point-in-bbox metric a single precise click is served better by direct imitation than by a multi-step crop$\to$locate$\to$\texttt{computer\_use} protocol, and non-GUI slices dilute GUI action patterns. We read this as a pointer to better action interfaces and mixture balancing rather than a failure of tool-use supervision (\dataset still lifts GUI $27.1\!\to\!31.6$). Deeper discussion in Limitations.
